Data: existing 5-min spot + premium stores suffice; population build = afternoon trend days only.
2. **Option-chain-native family** — entries keyed on the chain itself (intraday OI build-up migration, skew shifts), a data axis no current Bank family uses. Data: **does not exist historically** — needs a forward OI/chain snapshot collector (Upstox option chain, 5-min snapshots) run for a full month before any gate can be scored; this is a data-build-first brief.
3. **Expiry-window family** — a dedicated book for the monthly expiry day and the session before it (pinning / gamma-driven premium shapes), treating those days as their own population instead of ordinary days with an ITM-100 strike rule. Data: premium store already covers these days; population build = expiry-window days, Jan–Oct.

A standalone book that trades *only* expiry-day shapes is a new population. Data: premium store covers weekly chains with known late-October gaps — chain completion is part of the brief.
2. **Option-chain-native family** (as Bank #2, Nifty chain) — OI/skew/PCR-change entries; same forward-collector requirement; Nifty's chain is the more liquid one and the natural first build.
3. **Cross-asset overnight family** — entries triggered by overnight external moves (GIFT Nifty gap structure beyond the existing gap-fade, USDINR, US index futures) as a *standalone trigger source*, not a conditioning filter on existing keys (the agreement-conditioning form is closed; a standalone external-trigger population was never gated). **Sequencing note:** the chain-native families (Bank #2 / Nifty #2) share one data build — a forward option-chain snapshot collector — and cannot produce a gated number until it has run; the afternoon-pullback (Bank #1) and weekly-expiry (Nifty #1) families can be built and gated on existing stores immediately.
